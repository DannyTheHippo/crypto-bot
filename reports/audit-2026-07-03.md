## 2. Agent context was starved (must-fix — profitability)

- Evidence: `src/modules/strategy/strategy-host.ts:446` (pre-refactor) — `buildSnapshot` handed
  the agent a hardcoded-empty portfolio (`strategyId('')`, empty positions/openOrders), so the
  agent could not see its own position, entry, or PnL. Raw OHLCV only: no computed indicators.
  No decision memory: each decide saw only a point-in-time snapshot. The real position source
  existed but was unwired: `PortfolioStateService.forStrategy()`
  (`src/modules/execution/portfolio-state.service.ts:170-179`), already globally exposed via
  `PortfolioViewBridgeModule` (`src/app.module.ts:154-164`).
- Note: exec-report folding could NOT provide position state — `FillReport` carries no `side`
  field (`src/domain/types/exec-report.ts`) and `enqueueExecReport` had no production caller.
- Disposition: FIXED — host gained `portfolioFor` wired to `PORTFOLIO_VIEW.forStrategy(id)`;
  `AgenticStrategy` builds `AgentContext` (EMA 9/21, RSI-14, ATR-14, 1/5/20-bar returns via
  `src/domain/indicators/indicators.ts`; exact-string position summary; 10-deep decision ring).

## 3. Decision cadence uncontrolled; timeout too tight (must-fix — profitability/cost)

- Evidence: pre-refactor `strategy-host.ts` triggered a decide on EVERY folded event — ticker and
  book churn included — conflated only by the one-in-flight `busy` flag; `AGENT_CALL_TIMEOUT_MS =
5_000` (`strategy-host.ts:40`) is too tight for LLM calls, so a slow agent would silently never
  trade (signals past TTL reject `EXPIRED`); zero config surface (no model/timeout/interval
  knobs).
- Disposition: FIXED — closed-candle-only triggering (partial candles dropped entirely),
  ticker/book fold state without triggering, exec reports always trigger (fill awareness),
  `AGENTIC_MIN_DECISION_INTERVAL_MS` cadence gate, configurable `AGENTIC_TIMEOUT_MS` (default
  30s; host wall-clock backstop = client timeout + 2s so the client's abort fires first).

## 4. Paper maker fee 10× understated (should-fix — research economics)

- Evidence: `src/app.module.ts:347` — `fees: { makerBps: '1', takerBps: '10', ... }` in
  `DEFAULT_PAPER_CONFIG`, vs Binance VIP0 spot 10 bps both sides. Flattered any maker-heavy
  strategy's paper PnL by ~9 bps per maker fill.
- Disposition: FIXED — `makerBps: '10'`.

## 5. Latent PRECISION_OVERFLOW throw on the risk resize path (must-fix — correctness)

- Evidence: `src/domain/risk/evaluate.ts` derived clamps by unrounded division —
  `maxOrderNotional.div(workingPrice)` (:140), `headroom.div(workingPrice)` (:207) — and a
  band-edge multiplication `refMid.mul(maxBand.add(1))` (:126-129); F1 then validated BEFORE
  rounding: `roundToStep(makeQty(workingQty), ...)` (:241) and `roundToTick(makePrice(workingPrice),
...)` (:243). `checkPrecision` (`src/domain/types/money.ts:49-76`) throws
  `MoneyError('PRECISION_OVERFLOW')` above 18 decimal places, so a legitimate clamp (e.g. notional
  100 at price 3 → 33.333…) could crash the RiskEngine instead of returning RESIZED. `roundToStep`
  already accepted a raw `Decimal` for exactly this reason (money.ts:148-152); `roundToTick` did
  not.
- Disposition: FIXED — `roundToTick` widened to accept a raw `Decimal` (mirrored rationale
  comment); F1 rounds first, brands after; three regression cases added to
  `test/unit/risk/evaluate.spec.ts` (FAT_FINGER non-terminating quotient, EXPOSURE_LIMIT
  non-terminating quotient, PRICE_BAND 18-dp edge) plus a raw->18dp `roundToTick` case in the
  money spec. 100% risk-zone coverage retained.

## Disposition update — 2026-07-04 (agentic self-improvement harness)

A follow-on pass closed the observability, safety, and iteration gaps this audit's lane carried at
merge time. Mapped against the items above:

- **§1/§2/§3 (blind decisions, no memory of outcomes):** `agent_decisions` journal
  (`src/modules/persistence/repositories/agent-decision.repository.ts`,
  `agent-decision-journal.adapter.ts`, in-memory fallback) now persists every decide call;
  Prometheus gained `agent_decide_total`, `agent_tokens_total`, `agent_decide_latency_seconds`,
  `strategy_lifecycle`, `agentic_playbook_info`, and `playbook_validator_rejections_total`
  (`src/modules/observability/metrics.service.ts`, `agent-metrics-recorder.service.ts`) plus a
  strategies detail block on the health endpoint. The agent prompt (`agent-prompt.ts`) is now
  config-grounded (real 10/10bps fees, the sizing formula, venue constraints) with 1h/4h HTF
  context, and decisions carry outcome-annotated memory instead of a stateless point-in-time view.
- **§3 (DRAINING terminality) / error-taxonomy absence:** `anthropic-agent-client.ts` classifies
  every HTTP failure `RETRYABLE` or `FATAL` (`classifyHttpStatus`, `FATAL_STATUSES` = 400/401/
  403/404/422) with a retry-budget floor and a FATAL latch that short-circuits further `propose()`
  calls without another HTTP round-trip; AUTO-drain now has a cooldown recovery path
  (`AGENTIC_DRAIN_COOLDOWN_BASE_MS`/`_MAX_MS`) with OPERATOR-provenance override, replacing the
  prior one-way DRAINING state.
- **Kill-switch gap / unbounded spend:** `DailyLlmBudget` (`agent-budget.ts`) enforces
  `AGENTIC_MAX_CALLS_PER_DAY` / `AGENTIC_MAX_TOKENS_PER_DAY` per UTC day and
  `BudgetedAgentClient` refuses calls past either cap; a separate per-UTC-day
  `AGENTIC_MAX_ENTRIES_PER_DAY` caps `ENTER_LONG` decisions; paid LLM calls are now gated on kill
  switch state (no calls once tripped).
- **No offline iteration:** trade-triggered `ReflectionService` (`reflection.service.ts`) runs
  every `AGENTIC_REFLECTION_EVERY_N_TRADES` (default 10, 0 disables) closed trades, behind a
  7-day floor and a `RUNNING` kill-switch + `ACTIVE` lifecycle + budget-headroom precondition
  whitelist; it mints INACTIVE playbook candidates only — it never activates one (the method that
  writes a candidate is structurally incapable of promoting it). Promotion is human-pinned
  (`pnpm playbook:promote <version>`, max 1/UTC-day, `AGENTIC_PLAYBOOK_PIN` for rollback) through a
  versioned playbook store (`agent_playbook_versions`, seed v1) with quoted-data injection and a
  structural validator (`playbook-validator.ts`) rejecting free-form prose changes to risk-relevant
  fields.
- **Deferred (explicit, not fixed):** auto-promotion stays behind a manual gate — the reflection
  loop only proposes, never activates — pending a ≥30-matched-closed-trades evidence bar before an
  automatic promotion path is considered safe to build; shadow-mode (running a candidate playbook
  counterfactually against live decisions before promotion) is deferred to the same follow-on,
  pending the eval harness below providing a scoring baseline to compare against. An offline
  eval harness (`test/eval/agentic`, `pnpm eval:agentic`) and counterfactual scorer
  (`counterfactual-scoring.ts`) give a toy-research, CI-exempt way to iterate on playbook
  candidates without spending the daily LLM budget; module-level documentation lives in
  `src/modules/agentic-strategy/README.md`.
- Config/compose: all new `AGENTIC_*` knobs above are documented in `.env.example`
  (defaults matched to `src/modules/config/app-config.schema.ts`); `docker-compose.yml` needed no
  changes — `env_file: .env` already passes every new knob to the `app` service, and its explicit
  `environment:` overrides remain limited to the demo deployment's pinned strategy identity
  (`ACTIVE_STRATEGY`, `STRATEGY_INTERVAL`, `AGENTIC_MODEL`, `AGENTIC_WARMUP_BARS`) as before.
